------------------------------------------------------------

  docker-compose.yml       = starts MySQL + backend + frontend together

Step 5. Build and start the full stack in the background:

  1) Builds backend image from backend/Dockerfile
  2) Builds frontend image from booking-configuration/Dockerfile
  3) Starts mysql (if needed)
  4) Waits for MySQL health check
  5) Starts backend (migrates/bootstraps DB, serves API on 5006)
  6) Starts frontend (serves UI on 9000)

D) OPTIONAL: SEED / MIGRATE DATABASE
------------------------------------------------------------
If dashboards look empty or login users are missing:

  docker compose run --rm backend npm run db:seed


------------------------------------------------------------
E) ALTERNATIVE: RUN LOCALLY WITHOUT FULL DOCKER STACK
------------------------------------------------------------
Use this if you prefer Node processes on the host, with MySQL still available
(either Docker MySQL only, or a local MySQL install).

1) Start MySQL (example — Docker MySQL only):

  docker compose up -d mysql

2) In .env for local backend, use:

  DB_HOST=localhost
  (or 127.0.0.1)
  PORT=5006
  VITE_API_URL=http://localhost:5006

3) Backend terminal:

  cd backend
  npm install
  npm run db:migrate
  npm run db:seed
  npm run dev

4) Frontend terminal:

  cd booking-configuration
  npm install
  npm run dev

5) Open http://localhost:9000


------------------------------------------------------------
F) STOP / RESTART COMMANDS
------------------------------------------------------------
Stop everything:
  docker compose down

Restart:
  docker compose restart

Rebuild after big dependency changes:
  docker compose up --build -d

Reset database volume (DESTROYS DATA):
  docker compose down -v
